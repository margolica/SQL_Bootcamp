# SQL_bootcamp_day_06

## Улучшим клиентский опыт

Знакомство с добавлением новых бизнес-функций в нашу модель данных.

## Задачи

### Упражнение 00

Необходимо расширить нашу модель данных, чтобы включить новую бизнес-функцию — персональные скидки для клиентов. Создайте новую таблицу `person_discounts` с правилами:
- Установите атрибут `id` как первичный ключ.
- Установите внешние ключи для `person_id` и `pizzeria_id` с соответствующими таблицами.
- Установите явные имена для ограничений внешних ключей по шаблону `fk_{table_name}_{column_name}`.
- Добавьте атрибут `discount` для хранения значения скидки в процентах (используйте тип данных `numeric`).

### Упражнение 01

Необходимо заполнить таблицу `person_discounts` новыми записями на основе истории заказов из таблицы `person_order`. Используйте DML-запрос (`INSERT INTO ... SELECT ...`) для вставки данных, рассчитывая скидку по следующему псевдокоду:
- Если количество заказов = 1, то скидка = 10.5.
- Если количество заказов = 2, то скидка = 22.
- В остальных случаях скидка = 30.

Для генерации первичного ключа используйте конструкцию `ROW_NUMBER() OVER () AS id`.

### Упражнение 02

Необходимо написать SQL-запрос, который возвращает заказы с фактической ценой и ценой с учетом скидки для каждого человека в соответствующей пиццерии. Отсортируйте результат по имени человека и названию пиццы.

### Упражнение 03

Для улучшения согласованности данных и производительности создайте многоколоночный уникальный индекс `idx_person_discounts_unique`, который предотвращает дублирование пар значений `person_id` и `pizzeria_id`. Предоставьте SQL-запрос с доказательством использования индекса (`EXPLAIN ANALYZE`).

### Упражнение 04

Добавьте следующие ограничения для существующих столбцов таблицы `person_discounts`:
- `person_id` не должен быть NULL (используйте имя ограничения `ch_nn_person_id`).
- `pizzeria_id` не должен быть NULL (используйте имя ограничения `ch_nn_pizzeria_id`).
- `discount` не должен быть NULL (используйте имя ограничения `ch_nn_discount`).
- Значение по умолчанию для `discount` должно быть 0.
- Значение `discount` должно находиться в диапазоне от 0 до 100 (используйте имя ограничения `ch_range_discount`).

### Упражнение 05

Для соблюдения политик управления данными добавьте комментарии к таблице `person_discounts` и её столбцам, объясняющие бизнес-цели таблицы и её атрибутов.

### Упражнение 06

Создайте последовательность базы данных `seq_person_discounts` (начиная с 1) и установите значение по умолчанию для атрибута `id` таблицы `person_discounts`, чтобы оно автоматически бралось из последовательности. Убедитесь, что следующее значение последовательности корректно установлено на основе формулы "количество строк в таблице `person_discounts` + 1".
